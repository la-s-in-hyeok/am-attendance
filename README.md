# AM청년회 (남군산교회)

주일 예배 뒤에 목자·총무가 휴대폰으로 출석을 체크하고,
회장은 PC에서 보고서를 받고 인쇄하는 웹앱이에요.
엑셀 출석부와 카톡 손보고를 하나로 합쳤어요.
이제 출석부만이 아니라 **청년회 캘린더(행사 일정·회의록)** 와 **목장보고서** 도 함께 쓰는 **AM청년회 앱**이에요.

- 처음 설치하는 회장: **4번**을 위에서부터 차례대로 따라 해 주세요.
- 목자·총무에게 보낼 안내 글: **4-12** 에 복사해서 쓸 수 있게 있어요.

---

## 1. 이 앱이 하는 일

- **모두가 같은 주소 하나로**: 목자·총무 모두 같은 웹앱 주소를 열고, 휴대폰 **홈 화면에 추가**해서 앱처럼 써요.
  다른 휴대폰에서 누른 출석이 내 화면에도 바로 보여요. (인터넷 상태에 따라 늦어도 30초 안에)
- **출석 체크 (1부·2부 나눠서)**: 목장을 열고 **1부 예배 / 2부 예배** 를 고른 뒤 이름을 누르면 출석이에요.
  **1부는 노란색, 2부는 민트색**이에요. (엑셀 출석부의 노란 칸·민트 칸과 같아요)
  총 출석 = 1부 + 2부, 한 사람은 한 번만 세요.
- **결석 사유**: **결석** 을 누르고 `타지` / `연락두절` / `기타` 중에 골라요. 기타는 사유를 적어요.
- **완료 · 수정 + 알림**: 목장 체크를 다 하면 **완료** 를 눌러요. 다른 목자·총무 휴대폰에 알림이 가요.
  - **"OO목장 출석체크 완료했습니다"**
  - 완료한 뒤 고쳤을 때: **"OO목장 수정있어요!!!!!!"**
- **보고서 자동 작성**: 출석보고 탭의 **결석 심방보고** 와 **출석부 표** 가 저절로 채워져요.
  엑셀·Word 로 받거나 바로 인쇄 / PDF 할 수 있어요. 임원 단톡방에 올릴 글도 **글 복사하기** 한 번이면 돼요.
- **매주 새 출석부**: 주일마다 새 출석부가 저절로 생겨요. 지난 주일도 언제든 다시 볼 수 있어요.
- **통계**: 주일별 출석, 목장별 출석률, 개인별 출석 현황, 3주 이상 연속으로 못 나온 **관심이 필요한 사람**.
- **명단 관리**: 로그인한 사람은 누구나 새 가족 추가, 목장 옮기기, 명단에서 빼기를 할 수 있어요. 지난 기록은 그대로 남아요.
- **청년회 캘린더 (새 기능)**: 청년회 1년 행사표(2026년 기준)를 **2027년 달력**에 미리 넣어 두었어요.
  처음 열면 이번 달이 보이고, 위쪽 ‹ › 로 지난달·다음 달로 넘겨요. 일정은 알록달록한 파스텔 색이에요.
  - 달력이 화면을 꽉 채워요. 날짜를 한 번 더 누르거나 '+2' 처럼 가려진 칸을 누르면 그 날 일정 목록이 떠요.
  - **일정 추가 / 고치기 / 지우기**: 오른쪽 아래 둥근 **+** 버튼(고른 날에 추가). 지운 일정은 토스트의 **되돌리기** 로 살릴 수 있어요.
  - **끌어서 날짜 옮기기**: PC는 마우스로 끌어 놓고, 휴대폰은 일정을 **길게 눌렀다가** 끌어요.
  - **회의록**: 일정을 누르면 노션처럼 그 행사의 회의록을 쓰는 메모장이 열려요. 소제목·목록·체크 목록·▶ 토글을 쓸 수 있고, 저절로 저장돼요.
- **목장보고서 (새 기능)**: 각 목장이 매주 보고서(한글 hwp·hwpx, 워드 docx, PDF, 사진)를 직접 올려요.
  - 올리는 휴대폰 안에서 **PDF로 바뀌어요**. 서버·유료 서비스를 쓰지 않고, 원본 파일은 휴대폰 밖으로 나가지 않아요. 서버에는 바뀐 PDF만 저장돼요.
  - 바뀐 쪽을 미리 보고 '이대로 제출'. 낸 목장은 초록, 안 낸 목장은 빨강. 마감 전에는 자유롭게 지우고 다시 올려요.
  - **마감하기**: 안 낸 목장이 있어도 마감할 수 있고, 마감하면 더 못 올려요. 낸 보고서를 리더 → … → 부흥(목장 순서)으로 한 PDF로 합쳐서 받아요.
  - **낸 보고서는 낸 사람만 열어 볼 수 있어요.** 올린 휴대폰(브라우저)에서만 열어 볼 수 있어요.
    다른 사람에게는 '제출했어요 · 쪽수 · 낸 시각'만 보이고, 파일 이름·내용은 서버가 아예 보내 주지 않아요.
    바꾸기·지우기도 낸 휴대폰에서만 돼요.
    - 올릴 때 그 휴대폰에만 '주인 열쇠'(무작위 값)를 저장하고, 서버에는 그 열쇠의 지문만 적어요.
      그래서 **다른 휴대폰·다른 브라우저(예: 아이폰 홈 화면 앱과 Safari)·사이트 데이터를 지운 뒤에는 열 수 없어요.**
      이럴 때는 보고서 담당이 지워 주고 다시 올리면 돼요.
    - 이 기능이 생기기 전에 올린 보고서는 주인 열쇠가 없어서 아무도 열 수 없어요. 필요하면 담당이 지우고 다시 올려 주세요.
  - **보고서 담당 비밀번호**: 마감하기·마감 풀기·합친 PDF 받기·남이 낸 보고서 지우기는 **담당 비밀번호**를 아는 사람만 해요.
    - 처음(임시) 담당 비밀번호는 **0000** 이에요. 회장이 정해진 담당에게만 알려 주세요.
      **관리 탭 → 목장보고서 담당 비밀번호 바꾸기** 에서 숫자 4~8자리로 바꿀 수 있어요. 0000 은 짐작하기 쉬우니 담당이 정해지면 꼭 바꿔 주세요.
      비밀번호를 잊었으면 회장이 schema.sql 맨 아래 '급할 때 쓰는 명령'으로 0000 으로 되돌릴 수 있어요.
    - 공용 비밀번호(로그인)와는 따로예요. 한 번 맞게 넣으면 앱을 다시 열거나 로그아웃할 때까지만 기억해요 (휴대폰에 저장하지 않아요).
    - 한 기기에서 10분 안에 서로 다른 틀린 담당 비밀번호를 10번 넣으면 그 기기는 10분 동안 막혀요.
      모든 기기를 합쳐 10분 안에 서로 다른 틀린 값이 30개가 되면 잠시 모두 막혀요 (여러 곳에서 맞혀 보기 막기).
    - 보고서는 **같은 휴대폰, 같은 앱(홈 화면 앱이면 홈 화면 앱)** 에서 올리고 열어 주세요. 아이폰 Safari 는 7일 넘게 안 쓰면
      사이트 데이터를 지울 수 있어서, 그 뒤에는 자기 보고서도 열 수 없을 수 있어요(내용은 서버에 그대로 있고 합친 PDF 에는 들어가요).
  - 처음 한 번은 변환 프로그램(약 11MB)과 글꼴(약 3MB)을 받느라 몇 초 걸려요. 한글 글꼴 모양은 원본과 조금 다를 수 있어요(그림 PDF).
  - 옛 워드(.doc)는 못 바꿔요. 한글·워드에서 'PDF로 저장' 한 파일을 올리면 돼요.

### 화면 구성

휴대폰에서는 화면 아래, PC에서는 왼쪽에 메뉴 4개가 있어요. **출석부** · **캘린더** · **목장보고서** · **관리**

**출석부** 를 누르면 위쪽 파란 띠에 **출석 · 출석보고 · 통계** 가 제목처럼 나와요. 눌러서 옮겨 다니고,
다른 메뉴에 갔다가 출석부로 돌아오면 마지막으로 보던 곳(예: 출석보고)이 다시 열려요.
('보고서' 는 새 '목장보고서' 와 헷갈리지 않게 이름만 **출석보고** 로 바꿨어요. 안의 내용은 그대로예요)

| 메뉴 | 하는 일 |
|---|---|
| **출석부 → 출석** | 이번 주일 출석 체크 (목장 → 1부/2부 → 이름), 결석 사유, **완료 / 수정**. 오른쪽 위 **🔔 알림 켜기**. 새신자·방문·바나바 현황도 여기서 적어요. |
| **출석부 → 출석보고** | **결석 심방보고** 탭: 목장별 타지 / 기타(사유) / 연락두절, 엑셀·Word·인쇄/PDF, **글 복사하기**<br>**출석부 표** 탭: 엑셀 출석부와 같은 모양의 표, Word·엑셀·인쇄/PDF |
| **출석부 → 통계** | 주일별 출석, 관심이 필요한 사람, 목장별 출석률, 개인별 출석 현황 |
| **캘린더** | 청년회 행사 달력 (2027년 행사 미리 들어 있음), 일정 추가·고치기·지우기, 끌어서 날짜 옮기기, 일정마다 **회의록** |
| **목장보고서** | 목장별 주간 보고서 올리기(휴대폰에서 PDF로 바뀜) → 마감하면 목장 순서대로 PDF 하나로 합치기 |
| **관리** | 목장·목장원 추가/이동/빼기, 비밀번호 바꾸기, 데이터 백업, 홈 화면에 추가하는 방법, 로그아웃 |

## 2. 주일에 이렇게 써요

### 목자·총무: 출석 체크하고 완료 누르기

1. **출석** 탭에서 내 목장을 눌러요.
2. 위쪽에서 **1부** 또는 **2부** 를 고르고, 온 사람 이름을 눌러요.
   - 같은 이름을 한 번 더 누르면 취소돼요.
   - 1부로 눌렀는데 2부였다면: **2부** 를 고르고 이름을 다시 누르면 민트색으로 바뀌어요.
3. 안 온 사람은 이름 옆 **결석** → `타지` / `연락두절` / `기타`(사유 적기 → **기타로 저장**).
4. 다 했으면 화면 아래 **완료** 를 눌러요.
   - 아직 안 누른 사람(미확인)이 있으면 "그래도 완료할까요?" 하고 한 번 물어봐요.
   - "완료! 모두에게 알렸어요" 가 뜨면 끝이에요.

### 완료 → 수정 → 수정 완료

| 지금 상태 | 화면 | 누르면 | 다른 휴대폰에 가는 알림 |
|---|---|---|---|
| 완료 전 | 아래에 노란 **완료** 버튼 | **완료** | **"OO목장 출석체크 완료했습니다"** |
| 완료 | 이름이 **잠겨요** (실수로 바뀌지 않게) | **수정** | 없음 |
| 수정 중 | 다시 고칠 수 있어요 | **수정 완료** | **"OO목장 수정있어요!!!!!!"** |

- 완료된 목장에서 이름을 누르면 "완료된 목장이에요. 고치려면 '수정'을 눌러 주세요" 가 떠요. 새 가족 추가도 잠겨요.
- 서버도 막아요. 다른 휴대폰이 완료 전 화면을 열어 둔 채 이름을 눌러도 저장되지 않고 같은 안내가 떠요.
  (**수정** 을 누른 동안에는 어느 휴대폰에서나 고칠 수 있어요)
- **수정은 누구나 누를 수 있어요.** 모두 같은 비밀번호를 쓰니까 누가 눌렀는지는 구분하지 않아요.
- 출석 탭 첫 화면에 **완료 3 / 9 목장** 처럼 몇 목장이 끝났는지 나오고, 목장 카드에 **완료** / **수정 중** 표시가 붙어요.
- 목장 이름이 '믿음목장' 처럼 이미 '목장' 으로 끝나면 '목장' 을 두 번 붙이지 않아요.

### 완료 알림은 이렇게 와요

- **앱을 열어 둔 휴대폰**: 화면 위에 알림이 뜨고 소리·진동이 나요(되는 휴대폰만). 알림을 누르면 그 목장이 열려요.
- **앱을 닫아 둔 휴대폰**: 휴대폰 알림(Web Push)으로 와요. 회장이 4-5 ~ 4-7 을 해 두고, 각자 **🔔 알림 켜기** 를 한 번 눌러야 해요.
- 완료를 누른 내 휴대폰에는 알림이 오지 않아요.
- 알림에는 목장 이름만 들어가요. 사람 이름은 보내지 않아요.

### 회장·임원: 보고하기

**출석부 → 출석보고** 탭 위쪽에서 주일을 고르고, 아래 두 탭 중 하나를 골라요. (휴대폰은 결석 심방보고, PC는 출석부 표가 먼저 열려요)

**결석 심방보고** 탭

- 목장마다 **타지 / 기타(사유) / 연락두절** 이 정리돼요. 아직 체크 안 한 사람은 미확인으로 따로 보여요.
- **엑셀로 받기 / Word로 받기 / 인쇄 / PDF**: 고른 목장과 상관없이 항상 전체 목장이 한 표로 나와요. (Word·인쇄는 A4 가로)
- **글 복사하기**: **전체** 또는 목장 하나를 고르고 누른 뒤, 임원 단톡방에 붙여 넣어요.
  휴대폰에서는 옆의 **공유** 로 카톡을 바로 고를 수도 있어요. 이런 글이 만들어져요.

  ```
  [11월 15일 목장심방 : 새싹]
  - 온 사람 (4명)
   1부 : 홍길동, 김철수
   2부 : 이영희, 박민수
  - 안 온 사람
  *타지역 : 최수진
  *연락두절 : 정하늘, 한소망, 오지훈
  *기타 (사유) : 윤서연(시험 기간), 장도윤(일)
  ```

  (위 이름은 설명용으로 지어낸 이름이에요. **전체** 를 고르면 맨 위에 총 출석·출석률이 붙고, 목장별 글이 이어져요.)

**출석부 표** 탭

- 엑셀 출석부와 같은 모양의 표예요. 1부 출석은 노랑, 2부 출석은 민트로 칠해져요.
- 휴대폰에서는 표를 옆으로 밀어서 봐요. 이름을 누르면 사유가 보여요.
- **Word로 받기 / 엑셀로 받기 / 인쇄 / PDF**
  - 인쇄는 **전체 출석부**(A4 가로 한 장), **목장별로 한 장씩**(A4 세로), **한 목장만** 중에 골라요.
  - 인쇄 창에서 프린터 대신 **PDF로 저장** 을 고르면 PDF 파일이 돼요.

## 3. 지금 바로 체험해 보기 (내 컴퓨터에서)

서버 없이도 내 컴퓨터에서 써 볼 수 있어요. 이것을 **체험 모드**라고 해요.

> 체험 모드는 **이 기기의 이 브라우저에만** 저장돼요. 다른 사람과 함께 쓰려면 4번을 따라 해 주세요.

1. **Node.js 설치** (앱을 만들고 실행하는 프로그램이에요. 처음 한 번만)
   [nodejs.org](https://nodejs.org) 에서 **LTS** 라고 적힌 버튼으로 내려받아 설치해요. (버전 22 이상)
2. **터미널 열기** (글자로 컴퓨터에 명령하는 창이에요)
   - Mac: `응용 프로그램 → 유틸리티 → 터미널`. `cd ` (cd 다음에 한 칸 띄우기)를 치고, Finder 에서 이 `app` 폴더를 터미널 창으로 끌어다 놓은 뒤 `Enter`.
   - Windows: 파일 탐색기에서 이 `app` 폴더를 열고, 위쪽 주소창을 눌러 `cmd` 라고 치고 `Enter`.
3. 아래 두 줄을 한 줄씩 입력하고 `Enter` 를 눌러요.

   ```bash
   npm install
   npm run dev
   ```

   `npm install` 은 처음 한 번만 하면 돼요. (몇 분 걸릴 수 있어요)
4. 화면에 나온 주소 **http://localhost:5173** 를 크롬이나 사파리에서 열어요.
5. 비밀번호 **0000** 을 넣으면 시작해요.

> ⚠️ **체험 모드에는 우리 교회의 실제 명단이 들어 있어요.** (2026년 10월 11일 엑셀 출석부, 9개 목장 186명)
> 명단 파일은 `app/src/lib/seed.json` 이에요. 그래서 이 `app` 폴더는 함부로 남에게 보내거나 공개하면 안 돼요.
> - 서버에 연결해서 만든 앱(4번)에는 이 명단이 **들어가지 않아요.** 서버의 명단은 따로 넣어요(4-10).
> - 체험판을 일부러 만들어 인터넷에 올리면(`VITE_DEMO=1`) 명단이 그대로 공개되니 **올리지 마세요.**

끝낼 때는 터미널에서 `Ctrl` + `C` 를 눌러요.

처음 한 번만 1시간쯤 걸려요. 아래 순서대로 하나씩 해 주세요. (화면의 영어 글자는 조금 다를 수 있어요)

| 순서 | 할 일 |
|---|---|
| 4-1 ~ 4-4 | 서버 만들기, 설정 스크립트 실행, GraphQL 끄기, 주소·열쇠 복사 |
| 4-5 ~ 4-7 | **완료 알림 설정** (알림 열쇠 만들기, 알림 함수 올리기, 비밀 값 넣기) |

### 4-1. Supabase 가입하고 프로젝트 만들기

3. **Organization**(조직)을 만들라고 하면: 이름은 `AM청년회` 처럼 아무거나, Type 은 `Personal`, Plan 은 **Free** → **Create organization**.
4. **New project** 화면에서
   - **Project name**: `am-attendance` (아무 이름이나 괜찮아요)
   - **Database Password**: **Generate a password** 를 눌러 만들고, 따로 적어 두세요. (앱에서는 안 써요)
   - **Region**: **Northeast Asia (Seoul)**
   - **Create new project** 를 눌러요. 준비되는 데 1~2분 걸려요.

### 4-2. 서버 설정 스크립트 실행하기 (복사 → 붙여넣기 → Run)

1. 이 폴더 안의 `supabase/schema.sql` 파일을 메모장(Windows)이나 텍스트 편집기(Mac)로 열어요.
2. **전체 선택**(`Ctrl`+`A`, Mac은 `⌘`+`A`) → **복사**.
3. Supabase 왼쪽 메뉴에서 **SQL Editor** 를 눌러요.
4. **New query** (또는 `+`)를 누르고, 빈 칸에 **붙여넣기**.
5. 오른쪽 아래 **Run** 을 눌러요.
   - "destructive operation" 경고가 뜨면 **Run this query** 를 눌러도 괜찮아요. 기존 데이터는 지우지 않아요.
6. 아래에 **Success. No rows returned** 가 나오면 성공이에요.

> 이 스크립트는 여러 번 실행해도 안전해요. 명단·출석 기록·비밀번호는 그대로 남아요.
> 앱을 새 버전으로 바꿀 때마다 한 번씩 다시 Run 해 주세요. (아래 '새 버전으로 바꿀 때' 참고)

### 4-3. GraphQL 끄기 (보안)

우리 앱은 GraphQL 을 쓰지 않아요. 쓰지 않는 문은 닫아 두는 게 안전해요.

1. Supabase 왼쪽 메뉴 **Database** → **Extensions** 를 눌러요.
2. 검색 칸에 `pg_graphql` 을 쳐요.
3. 스위치가 켜져 있으면 눌러서 **끄고**, 확인 창이 뜨면 **Disable** 을 눌러요. (이미 꺼져 있으면 그대로 두면 돼요)

- 화면에서 찾기 어려우면 **SQL Editor** 에 `drop extension if exists pg_graphql;` 한 줄을 붙여 넣고 **Run** 해도 같아요.
- 설정 스크립트에도 GraphQL 로 비밀번호를 여러 번 맞혀 보는 우회를 막아 두었지만, 꺼 두면 더 안전해요.

### 4-4. 서버 주소와 열쇠 복사하기

1. 왼쪽 아래 **Project Settings**(톱니바퀴) → **API** 를 눌러요.
   (화면이 다르면 **Data API** 에 주소가, **API Keys** 에 열쇠가 있어요. 프로젝트 첫 화면 위쪽 **Connect** 버튼에도 나와요.)
2. 두 가지를 복사해서 메모장에 붙여 둬요.
   - **Project URL**: `https://abcdefgh.supabase.co` 처럼 생긴 주소
   - **anon public** 키: `eyJ...` 로 시작하는 아주 긴 글자
     (새 화면에서는 **Publishable key**, `sb_publishable_...` 로 시작해요. 이것을 써도 돼요.)

> ⚠️ **service_role** 키나 **Secret key** 는 절대 쓰지 마세요. 모든 권한을 가진 열쇠예요.
> anon(publishable) 키는 앱 안에 들어가도 괜찮은 열쇠예요. 공용 비밀번호 없이는 이 키로 아무것도 볼 수 없게 막아 두었어요.

### 4-5. 알림 열쇠(VAPID) 만들기

앱을 닫아 둔 휴대폰에 알림을 보내려면 열쇠 한 쌍(Public Key, Private Key)이 필요해요.

1. 3번의 **1~2단계**처럼 Node.js 를 설치하고 이 `app` 폴더에서 터미널을 열어요.
2. 아래 한 줄을 입력하고 `Enter`.
   ```bash
   npx web-push generate-vapid-keys
   ```
   "Ok to proceed?" 라고 물으면 `y` 를 누르고 `Enter`.
3. `Public Key:` 아래 한 줄, `Private Key:` 아래 한 줄이 나와요. 둘 다 메모장에 복사해 둬요.

> ⚠️ **Private Key 는 Supabase 의 Secrets(4-7)에만** 넣어요. 앱의 `.env` 나 Vercel 환경 변수에는 넣지 마세요.
> (`VITE_` 로 시작하는 값은 앱 파일에 그대로 들어가서 누구나 볼 수 있어요)
> 열쇠는 한 번 만들면 계속 써요. 바꾸면 모두가 앱을 한 번씩 다시 열어야 해요.

### 4-6. 알림 함수(am-notify) 올리기

1. Supabase 왼쪽 메뉴 **Edge Functions** 를 눌러요.
2. **Deploy a new function** → **Via Editor** 를 눌러요.
3. 이 폴더의 `supabase/functions/am-notify/index.ts` 를 메모장으로 열고 **전체 선택 → 복사**.
4. 편집 칸에 원래 있던 글을 **모두 지우고** 붙여 넣어요.
5. 아래쪽 함수 이름 칸에 `am-notify` 를 적어요. (**정확히 이 이름**. 다르면 알림이 안 가요)
6. **Deploy function** 을 누르고 끝날 때까지 기다려요.
7. 올라간 함수 화면에서 **Details** 탭 → **Verify JWT** 스위치를 **끄고** → **Save changes**.
   (스위치 이름이 "Enforce JWT verification" 이나 "Verify JWT with legacy secret" 일 수 있어요.
   켜 두면 `sb_publishable_` 열쇠를 쓰는 앱에서 알림이 안 가요. 꺼도 괜찮아요: 이 함수는 완료를 누른 휴대폰이
   서버에게 받은 한 번 쓰는 알림 열쇠가 있어야만 알림을 보내요. 공용 비밀번호는 이 함수로 보내지 않아요.)

### 4-7. 알림 비밀 값(Secrets) 넣기

1. **Edge Functions** 왼쪽 안쪽 메뉴의 **Secrets** 를 눌러요. (또는 Project Settings → Edge Functions)
2. 아래 세 개를 이름(Key)과 값(Value)으로 넣고 **Save** 를 눌러요.

   | 이름 (정확히) | 값 |
   |---|---|
   | `VAPID_PUBLIC_KEY` | 4-5의 **Public Key** |
   | `VAPID_PRIVATE_KEY` | 4-5의 **Private Key** |
   | `VAPID_SUBJECT` | `mailto:회장이메일@gmail.com` (회장 이메일로 바꿔요. 앞의 `mailto:` 는 그대로) |

   `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 는 Supabase 가 알아서 넣어 줘요. 따로 넣지 않아요.

### 4-8. 앱을 인터넷에 올리기

두 방법 중 하나를 골라요. **GitHub 이 처음이라면 방법 A** 가 가장 쉬워요.
어느 쪽이든 넣는 값은 세 개예요.

| 이름 | 값 |
|---|---|
| `VITE_SUPABASE_URL` | 4-4의 Project URL |
| `VITE_SUPABASE_ANON_KEY` | 4-4의 anon public (또는 Publishable) 키 |
| `VITE_VAPID_PUBLIC_KEY` | 4-5의 **Public Key** (Private Key 아님!) |

#### 방법 A. 내 컴퓨터에서 만들어 Netlify Drop 에 끌어다 놓기 (GitHub 필요 없음)

1. 이 `app` 폴더에서 터미널을 열어요. (3번의 2단계)
2. 설정 파일 `.env` 를 만들어요. 아래 명령을 한 줄씩 입력해요.
   - Mac:
     ```bash
     cp .env.example .env
     open -e .env
     ```
   - Windows:
     ```bash
     copy .env.example .env
     notepad .env
     ```
3. 열린 파일에서 `=` 뒤에 위 세 값을 붙여 넣고 저장해요. (따옴표나 띄어쓰기 없이)
   ```
   VITE_SUPABASE_URL=https://abcdefgh.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...(아주 긴 글자)
   VITE_VAPID_PUBLIC_KEY=BKx...(긴 글자)
   ```
4. 터미널에서 앱을 만들어요.
   ```bash
   npm install
   npm run build
   ```
   끝나면 `app` 폴더 안에 **`dist`** 폴더가 생겨요. 이것이 완성된 앱이에요.
   - **"Supabase 설정이 없어요"** 오류로 멈추면 `.env` 의 앞 두 값이 비어 있는 거예요. 3단계를 다시 확인해 주세요.
5. [app.netlify.com](https://app.netlify.com) 에 **먼저 무료 가입하고 로그인**해요. (로그인하지 않고 올리면 잠시 뒤 사이트가 사라질 수 있어요)
6. [app.netlify.com/drop](https://app.netlify.com/drop) 을 열고, **`dist` 폴더를 통째로** 화면에 끌어다 놓아요.
7. 잠시 뒤 `https://멋진-이름-123.netlify.app` 같은 주소가 생겨요. 이것이 우리 출석부 주소예요.
8. 주소를 바꾸려면: **Site configuration → Change site name** 에서 `am-namgunsan` 처럼 바꾸면 `https://am-namgunsan.netlify.app` 이 돼요.

다시 올릴 때는 4단계(`npm run build`)를 하고, Netlify 사이트의 **Deploys** 탭에 새 `dist` 폴더를 끌어다 놓으면 돼요. 주소는 그대로예요.

#### 방법 B. GitHub + Vercel (한 번 해 두면 고칠 때마다 저절로 올라가요)

> ⚠️ **저장소는 반드시 Private(비공개)로 만들어 주세요.**
> 이 `app` 폴더에는 **우리 교회의 실제 명단**(`src/lib/seed.json`, 체험 모드용)이 들어 있어요.
> Public(공개)으로 만들면 세상 누구나 이름을 볼 수 있어요.
> 엑셀 출석부 파일(`.xlsx`)은 `app` 폴더 **밖에** 두고, 저장소에 넣지 마세요.

1. [github.com](https://github.com) 에 무료 가입하고 로그인해요.
2. [GitHub Desktop](https://desktop.github.com) 을 설치하고, 처음 화면에서 **Sign in to GitHub.com** 으로 로그인해요.
3. GitHub Desktop 에서 **File → Add Local Repository… → Choose…** 를 누르고 이 `app` 폴더를 골라요.
   "This directory does not appear to be a Git repository" 가 나오면 그 안의 **create a repository** → **Create Repository**.
4. 위쪽의 **Publish repository** 를 눌러요.
   - **Name**: `am-attendance`
   - **Keep this code private** 에 **체크(✔)** 가 되어 있는지 꼭 확인해요. ← 이것이 Private 이에요
   - **Publish Repository** 를 눌러요.
5. [github.com](https://github.com) 에서 방금 올린 저장소를 열어, 이름 옆에 **Private** 라고 적혀 있는지 확인해요.
   - **Public** 이라고 나오면: 저장소 **Settings → General → 맨 아래 Danger Zone → Change visibility → Change to private**.
   - `node_modules`, `dist`, `.env` 는 올라가지 않아요. (`.gitignore` 에 적혀 있어요)
6. [vercel.com](https://vercel.com) 에서 **Sign Up → Continue with GitHub** 로 무료 가입해요. (Hobby 플랜)
   GitHub 권한을 물어보면 **이 저장소(am-attendance)만** 허용하면 돼요.
7. **Add New… → Project** → 방금 만든 저장소 옆의 **Import**.
8. **Framework Preset** 이 **Vite** 인지 확인해요.
9. **Environment Variables** 를 펼쳐서 위 표의 **세 개**를 넣어요. (앞의 두 값이 없으면 빌드가 일부러 멈춰요)
10. **Deploy** 를 누르고 1~2분 기다리면 `https://am-attendance.vercel.app` 같은 주소가 생겨요.

> 환경 변수를 나중에 바꿨거나 빠뜨렸다면 **Settings → Environment Variables** 에서 고친 뒤
> **Deployments → 맨 위 항목의 ⋯ → Redeploy** 를 눌러야 적용돼요.

   2. 엑셀 파일을 골라요.
   3. 시트가 여러 개면 쓸 시트를 골라요. 보통 **맨 앞 시트 = 가장 최근** 명단이에요. 목장 이름과 인원이 맞는지 봐요.
   4. **N명 불러오기**(예: "186명 불러오기") → **불러오기**. 목장, 목자·총무, 목장원이 한 번에 들어가요.
   - 엑셀 파일은 이 PC에서만 읽고, 명단만 서버에 저장해요. 파일 자체는 어디에도 올라가지 않아요.
   - 두 사람이 동시에 눌러도 명단은 한 번만 들어가요.
   - 새 목장 편성으로 시작하려면: **빈 상태로 시작하기** → **목장 추가** → 목장마다 **목장원 추가** 에서
     이름을 쉼표(,)나 줄바꿈으로 나눠 **여러 명을 한꺼번에** 붙여 넣어요.
   - 목자·총무 표시는 관리 탭에서 이름을 누르면 바꿀 수 있어요.

### 4-11. 알림 시험하기 (휴대폰 두 대)

> ⚠️ **솔직한 안내: 앱을 닫아 둔 휴대폰 알림(Web Push)은 실제 휴대폰·실제 Supabase 에서 끝까지 시험해 보지 못했어요.**
> (서버 함수는 가짜 서버로, 화면 알림은 체험 모드의 두 탭으로만 확인했어요.) 목자·총무에게 알리기 전에 꼭 한 번 해 봐 주세요.

1. 휴대폰 **A**, **B** 두 대에서 주소를 열고 **홈 화면에 추가** → 홈 화면 아이콘으로 열고 로그인해요. (방법은 4-12의 안내 글)
   아이폰이 있으면 한 대는 아이폰으로 해 보세요.
2. 두 휴대폰 모두 **출석** 탭 오른쪽 위 **🔔 알림 켜기** → **허용**. (켜지면 종 모양이 채워져요)
3. **B** 는 홈 버튼을 눌러 앱을 닫아요.
4. **A** 에서 목장 하나를 열고 아래 **완료** 를 눌러요. (미확인이 남았다고 물으면 **완료**)
   → **B** 에 **"OO목장 출석체크 완료했습니다"** 가 오면 성공이에요.
5. **A** 에서 **수정** → **수정 완료** → **B** 에 **"OO목장 수정있어요!!!!!!"** 가 오는지 봐요.
6. 시험이 끝나면 완료 표시를 지워요. **SQL Editor** 에서 날짜만 시험한 주일로 바꿔 **Run**.
   (날짜는 출석 탭 위쪽에 보이는 주일이에요)
   ```sql
   delete from public.group_days where date = '2026-11-15';
   ```

알림이 안 오면 6번 자주 묻는 질문의 **"앱을 닫아 두면 알림이 안 와요"** 를 봐 주세요.
종 모양을 누르면 나오는 **시험 알림** 은 그 휴대폰의 알림 허용만 확인해요. 서버를 거치는 진짜 알림은 위처럼 두 대로 확인해요.

### 4-12. 목자·총무에게 알리기

1. 아래 안내 글의 주소를 우리 주소로 바꿔서 **목자·총무 단톡방**에 올려요.
2. **비밀번호는 단톡방에 쓰지 말고** 따로(직접 말로, 또는 개인톡으로) 알려 줘요.

#### 목자·총무 단톡방에 보낼 안내 (복사해서 쓰세요)

```
[AM청년회 앱 안내]
이제 주일 출석은 이 주소에서 체크해요.
https://(우리 앱 주소)
비밀번호는 따로 알려 드려요.

1) 홈 화면에 추가 (처음 한 번)
- 카톡에서 열렸으면 메뉴(⋮ 또는 ⋯) → '다른 브라우저로 열기'를 먼저 눌러요
- 아이폰: 사파리로 열기 → 아래쪽 공유 버튼(네모+화살표) → '홈 화면에 추가' → '추가'
- 안드로이드: 크롬으로 열기 → 오른쪽 위 ⋮ → '홈 화면에 추가'(또는 '앱 설치')

2) 홈 화면의 'AM청년회' 아이콘으로 열고 비밀번호 입력
- '이 기기에서 로그인 유지'를 체크해 두면 다음부터 바로 열려요

3) 출석 화면 오른쪽 위 '🔔 알림 켜기'를 한 번 눌러 '허용'
- 다른 목장이 완료하면 알림이 와요
- 아이폰은 꼭 홈 화면 아이콘으로 연 다음에 눌러 주세요 (iOS 16.4 이상)

4) 주일에 체크하는 법
- 출석부 → 출석 → 내 목장 → 위에서 1부/2부 고르기 → 온 사람 이름 누르기 (1부 노랑, 2부 민트)
- 안 온 사람은 '결석' → 타지 / 연락두절 / 기타(사유 적기)
- 다 했으면 아래 '완료' → "OO목장 출석체크 완료했습니다" 알림이 가요
- 완료하면 실수로 바뀌지 않게 잠겨요. 고칠 게 있으면 '수정' → 고치기 → '수정 완료'
  → "OO목장 수정있어요!!!!!!" 알림이 가요
```

### 새 버전으로 바꿀 때

1. 새 `supabase/schema.sql` 을 4-2처럼 **한 번 더 Run** 해요. (데이터는 그대로예요)
2. `supabase/functions/am-notify/index.ts` 가 바뀌었다면 Supabase **Edge Functions → am-notify → Code** 에 새 내용을 붙여 넣고 다시 **Deploy**.
   > ⚠️ **알림 열쇠 버전(이번 버전)으로 바꿀 때는 1·2·3 을 모두 해야 해요.** 앱을 꺼 둔 휴대폰 알림(Web Push)이
   > 공용 비밀번호 대신 한 번 쓰는 알림 열쇠로 바뀌어서, 셋 중 하나라도 예전 것이면 그 사이에는 Web Push 만 안 가요.
   > (앱을 열어 둔 휴대폰의 화면 알림과 출석·완료 저장은 그대로 돼요)
3. 앱을 다시 올려요. 방법 A는 `npm run build` → 새 `dist` 를 **Deploys** 탭에 끌어다 놓기, 방법 B는 저장소에 올리면 저절로 돼요.

#### 캘린더가 들어간 버전(AM청년회)으로 바꿀 때

- ⚠️ **`supabase/schema.sql` 을 꼭 한 번 더 Run 해 주세요.** 캘린더 일정·회의록, 목장보고서(보고서 목록 표와
  Storage 의 비공개 보관함 `am-reports`)가 새로 생겨요.
  Run 하지 않으면 캘린더·목장보고서 탭에 '서버 설정을 새로 해야 해요'가 떠요. (출석·출석보고·통계는 그대로 돼요)
- 2027년 행사 일정(31개)은 **처음 Run 할 때 한 번만** 들어가요. 나중에 일정을 다 지우고 다시 Run 해도 또 생기지 않아요.
- 앱 이름이 **AM청년회** 로 바뀌었어요. 이미 홈 화면에 추가해 둔 아이콘은 이름이 바로 안 바뀔 수 있어요.
  - 안드로이드: 며칠 안에 저절로 바뀌어요. (휴대폰이 앱 정보를 다시 확인할 때)
  - 아이폰: 예전 이름('AM 출석부')이 그대로 남아요. 이름까지 바꾸려면 아이콘을 지우고 Safari에서 다시 ‘홈 화면에 추가’ 해요.
    이때는 비밀번호를 다시 넣고 **🔔 알림 켜기** 도 다시 해야 해서, 꼭 바꾸지 않아도 돼요. (쓰는 데는 문제없어요)
  - 단톡방 공지에 한 줄: "앱 이름이 AM청년회로 바뀌었어요. 홈 화면 아이콘 이름은 예전 그대로일 수 있어요."

schema.sql 을 다시 Run 하지 않으면 이런 일이 생겨요.

- **완료 / 수정** 을 누르면 "서버 설정이 예전 버전이라 '완료'를 쓸 수 없어요" 가 떠요.
- 2부로 체크해도 서버에는 1부로 저장돼요.
- 엑셀 명단 불러오기에서 "서버 설정이 예전 버전이라 엑셀 명단을 넣을 수 없어요" 가 떠요.
- 비밀번호를 여러 번 틀린 사람 때문에 모든 휴대폰이 함께 잠길 수 있어요. (기기별 잠금이 없는 예전 버전)
- 캘린더 탭에서 일정을 불러오지 못하고, 일정·회의록을 저장할 수 없어요.
- 목장보고서 탭에서 보고서를 올리거나 마감할 수 없어요.
- (낸 사람만 보기·담당 비밀번호 버전) 목장보고서 탭에 '서버 설정을 새로 해야 해요'가 뜨고, 보고서를 볼 수도 낼 수도 없어요.

#### 목장보고서 '낸 사람만 보기 + 담당 비밀번호' 버전으로 바꿀 때

- ⚠️ **`supabase/schema.sql` 을 꼭 한 번 더 Run 해 주세요.** 예전 보고서 함수(누구나 모든 보고서를 열 수 있던 것)는 지워지고,
  낸 사람 확인·담당 비밀번호가 들어간 새 함수로 바뀌어요. 정한 담당 비밀번호는 다시 Run 해도 지워지지 않아요.
- ⚠️ **앱 올리기와 SQL Run 은 몇 분 안에 함께 해 주세요.** SQL 을 먼저 Run 하면 예전 앱의 목장보고서 탭이 멈추고,
  앱을 먼저 올리면 '서버 설정을 새로 해야 해요'가 떠요. (출석부·캘린더는 어느 쪽이든 그대로 돼요)
- Run 한 다음 **보고서를 걷는 사람이 관리 탭에서 담당 비밀번호를 정해 주세요.** (처음 비밀번호는 없어요)
- 이미 올라와 있던 보고서는 '제출'로 그대로 보이지만, **주인 열쇠가 없어서 아무도 열 수 없어요.**
  열어 봐야 하면 담당이 '담당 비밀번호로 지우기'로 지우고 그 목장이 다시 올려 주세요. (마감 뒤 합친 PDF 에는 그대로 들어가요)
- 담당 비밀번호를 잊었으면 schema.sql 맨 아래 '급할 때 쓰는 명령'으로 비운 뒤 관리 탭에서 다시 정하면 돼요.

## 5. 비용 · 보안 · 백업

### 비용: 무료로 충분해요

- **Supabase 무료 플랜**: 저장 공간 500MB. 우리 출석 기록은 1년에 1만 줄(몇 MB) 정도라 넉넉해요.
  알림 함수(Edge Functions)도 무료 범위 안에서 충분해요. (완료 한 번 = 한 번 실행)
- **Netlify / Vercel 무료 플랜**: 한 달 100GB 정도까지 무료예요. 우리 앱은 한 번 여는 데 1~2MB 라 걱정 없어요.
- ⚠️ **Supabase 무료 프로젝트는 일주일쯤 아무도 쓰지 않으면 일시 중지돼요.** 매주 주일에 쓰면 계속 켜져 있어요.
  몇 주 쉬었다면 Supabase 대시보드에서 프로젝트를 열고 **Restore project** 를 누르면 돼요. 데이터는 그대로예요.
  아주 오래(몇 달) 멈춰 두면 복구가 어려울 수 있으니, 쉬는 동안에도 가끔 앱을 열고 백업을 받아 두세요.
- 무료 범위나 정책은 바뀔 수 있어요. 대략적인 안내로 봐 주세요.

### 보안 메모

- **GitHub 저장소는 꼭 Private** 으로 두세요. `app` 폴더에 실제 명단(체험 모드용)이 들어 있어요. (4-8 방법 B)
- **처음 비밀번호 `0000` 은 가장 먼저 바꿔 주세요.** (4-10)
- 비밀번호는 **6자리 이상**(최대 8자리) 숫자를 권장해요. 4자리는 1만 가지뿐이라 쉽게 맞힐 수 있어요.
  `123456`·`000000`·생일·교회 전화번호 같은 쉬운 숫자는 피해 주세요.
- **GraphQL 은 꺼 두세요.** (4-3) 우리 앱은 쓰지 않아요.
- **잠금은 기기(인터넷 연결)마다 따로예요.** 한 기기에서 10분 안에 서로 다른 틀린 비밀번호를 **10번** 넣으면,
  **그 기기만 최대 10분** 기다려야 해요. 다른 휴대폰은 그대로 써요.
  - 같은 와이파이(예: 교회 와이파이)를 쓰는 기기는 한 묶음으로 셀 수 있어요. 급하면 휴대폰 데이터(LTE/5G)로 바꾸면 돼요.
  - 같은 틀린 비밀번호를 여러 번 넣은 것은 한 번으로 세요. (비밀번호를 바꾼 뒤 예전 비밀번호로 열려 있던 휴대폰 때문에 잠기지 않도록)
  - 누군가 여러 곳에서 한꺼번에 맞혀 보면(10분에 서로 다른 틀린 비밀번호 100개 이상), **처음 보는 기기**는 잠시 로그인을 못 해요.
    최근 30일 안에 로그인했던 기기·와이파이는 그대로 써요.
- **주소와 비밀번호는 임원·목자·총무에게만** 알려 주세요. 공개 게시판이나 큰 단톡방에 올리지 마세요.
- 임원이 바뀌는 때(새해, 새 학기)에는 비밀번호도 바꿔 주세요. 바꾸면 다른 휴대폰들은 새 비밀번호로 다시 로그인해요.
- **service_role / Secret key, 알림 Private Key** 는 앱에 넣지 마세요. Private Key 는 Supabase Secrets 에만 있어요.
- **목장보고서는 낸 사람만** 열어 볼 수 있어요. 서버가 확인해요(화면에서 숨기기만 하는 게 아니에요).
  공용 비밀번호를 아는 사람도 남이 낸 보고서의 파일 경로·이름·내용은 받을 수 없어요.
  모든 보고서를 한꺼번에 받는 것(합친 PDF)은 **보고서 담당 비밀번호**를 아는 사람만 할 수 있어요.
  담당 비밀번호는 처음에 없어서 걷는 사람이 정해야 하고, 걷는 사람이 바뀌면(새해) 다시 바꿔 주세요. (관리 탭)
  보관함 규칙은 받기·올리기·지우기 허락표를 그 동작에만 쓰게 해서, Storage '목록 보기'로 남의 파일 이름을 알아낼 수도 없어요.
- 서버의 표(테이블)는 모두 잠겨 있고, 비밀번호를 확인하는 정해진 기능으로만 읽고 쓸 수 있어요.
  Supabase Security Advisor 에 "RLS Enabled No Policy" 가 보여도 **일부러 그렇게 만든 것**이라 정상이에요.

### 백업

- **관리 → 데이터 백업 받기** 를 누르면 목장·명단·출석 기록 전체가 파일 하나(`.json`)로 저장돼요.
- 한 달에 한 번, 그리고 목장 개편 전에는 꼭 받아서 PC나 구글 드라이브에 보관해 주세요.
  (이 파일에는 이름이 들어 있어요. 단톡방 같은 곳에 올리지 마세요.)
- 출석보고 탭에서 받은 **Word·엑셀 파일**도 종이 출석부처럼 기록으로 남겨 두면 좋아요.
- ⚠️ **솔직한 안내: 앱에는 아직 '백업 파일에서 되살리기' 버튼이 없어요.** JSON 백업은 기록을 잃지 않게 보관하는 용도예요.
  서버 데이터를 예전 상태로 되돌려야 할 때는 아래 중 하나로 해요.
  - **Supabase 자체 백업**: Supabase 대시보드 → **Database → Backups** 에 날짜별 백업이 보이면,
    원하는 날짜의 **Restore** 로 되돌릴 수 있어요. 그 뒤에 입력한 출석은 사라지고, 몇 분 동안 앱이 멈춰요.
    이 기능은 **요금제에 따라 없거나 제한될 수 있어요.**
  - **개발자에게 부탁하기**: 받아 둔 JSON 백업 파일을 주면, 개발자가 서버에 다시 넣어 줄 수 있어요.

## 6. 자주 묻는 질문

**Q. 앱을 닫아 두면 알림이 안 와요.**
위에서부터 하나씩 확인해 주세요.
1. **그 휴대폰**: 출석 탭 오른쪽 위 종 모양이 채워져 있나요? 아니면 **🔔 알림 켜기** → **허용**.
   - 아이폰은 사파리가 아니라 **홈 화면 아이콘**으로 열어서 눌러야 해요. **iOS 16.4 이상**이 필요해요.
   - "알림이 막혀 있어요" 가 뜨면 휴대폰 **설정 → 알림** (안드로이드는 크롬 사이트 설정)에서 출석부 알림을 허용해요.
   - 방해 금지·집중 모드가 켜져 있으면 알림이 조용히 와요.
2. **앱**: 4-8에서 `VITE_VAPID_PUBLIC_KEY` 를 넣고 **다시 올렸나요?** (Vercel은 Redeploy)
3. **알림 함수**: Supabase **Edge Functions** 에 이름이 정확히 `am-notify` 인지, **Verify JWT** 가 꺼져 있는지 봐요. (4-6)
   - 앱·`schema.sql`·`am-notify` 셋 중 하나만 새 버전이면 Web Push 가 안 가요. 셋 다 같은 버전으로 올렸는지 봐요. ("새 버전으로 바꿀 때")
4. **비밀 값**: Secrets 에 세 개가 다 있는지, `VAPID_PUBLIC_KEY` 가 앱에 넣은 Public Key 와 **같은 값**인지 봐요. (4-7)
5. 그래도 안 되면 **Edge Functions → am-notify → Logs** 에 오류가 보여요. 그 화면을 개발자에게 보여 주세요.

알림 설정을 나중에 마쳐도 괜찮아요. 이미 **알림 켜기** 를 눌러 둔 휴대폰은 앱을 한 번 열면 저절로 등록돼요.

**Q. 앱을 열어 둔 휴대폰에도 화면 알림이 안 오고, 다른 휴대폰의 체크가 30초쯤 늦게 보여요.**
실시간 연결이 막혀 있는 경우예요. (출석은 30초마다 다시 맞춰져서 그대로 저장돼요)
Supabase **Project Settings → Realtime** 에 **Allow public access** 같은 항목이 꺼져 있으면 켜 주세요.
그런 항목이 없거나 이미 켜져 있으면 인터넷 상태를 확인해 주세요.

**Q. 완료를 잘못 눌렀어요 / 완료한 목장을 고치고 싶어요.**
목장 화면 아래 **수정** → 고치기 → **수정 완료**. 다른 사람들에게 "OO목장 수정있어요!!!!!!" 가 가요.
누구나 누를 수 있어요.

**Q. 새해에 목장을 새로 편성해요.**
관리 탭에서 이름을 누르고 **다른 목장으로 옮기기**를 하면 돼요. 새 목장은 **목장 추가**로 만들어요.
옮겨도 **지난 출석 기록은 원래 목장에 그대로** 남아서, 지난 보고서와 통계가 바뀌지 않아요.
없어지는 목장은 **목장 삭제**를 해도 지난 기록은 남아요. 편성을 바꾸기 전에 **데이터 백업**을 한 번 받아 두세요.

**Q. 목장 옮기기·명단에서 빼기는 언제부터 적용돼요?**
- **월~토요일**에 하면 **다음 주일 출석부부터** 적용돼요. 이미 보고한 지난 주일 출석부는 그대로 남아요.
- **주일 당일**에 하면 **그날 출석부부터** 적용돼요. (예배 뒤에 잘못 넣은 것을 바로 고칠 수 있게)
- 날짜를 바꿔 지난 주일이나 다음 주일 출석부를 열어 둔 채로 하면, **그 주일부터** 적용돼요.
- 정확한 날짜는 옮기기·빼기 화면에 나와요. 새 가족 **추가**는 추가 화면에 적힌 주일 출석부부터 나와요.

**Q. 목장을 옮긴 사람이 지난 주일 출석부에서 새 목장에 나와요.** (알려진 한계)
앱은 "언제 어느 목장이었는지" 이력을 따로 저장하지 않아요.
그래서 옮기기 **전 주일 중 그 사람의 기록이 없는 주일**(미확인)을 열면, 그 사람이 **새 목장**에 보여요.
출석·결석 기록이 있는 주일은 **원래 목장**에 그대로 보여요.
지난 주일 출석부를 다시 볼 일이 있다면, 옮기기 전에 그 주일들의 미확인을 먼저 채워 두면 좋아요.

**Q. 새 가족이 왔어요.**
출석 탭에서 그 목장을 열고 아래쪽에 이름을 적어 추가하거나, 관리 탭의 **목장원 추가**를 써요.
아직 목장에 배정되지 않은 새신자·새친구나 방문자는 출석 탭 아래쪽 **새신자 / 새친구**, **방문** 칸에 적어요. 총 출석 인원에 더해져요.

**Q. 지난 주 출석을 잘못 눌렀어요.**
출석 탭 위쪽 날짜 옆 화살표로 지난 주일로 가서 고치면 돼요. 그 목장이 완료돼 있으면 먼저 **수정** 을 눌러요.
다 고친 뒤에는 이번 주일로 돌아오는 것을 잊지 마세요.

**Q. 1부·2부 예배는 어떻게 나눠서 체크해요?**
목장을 열고 위쪽 **1부 / 2부** 중 하나를 고른 뒤 이름을 눌러요. 1부는 **노란색**, 2부는 **민트색**이에요.
- 앱을 다시 열면 1부로 돌아와요. (지난주에 2부로 두고 잊어도 다음 주에 모두 2부로 칠해지지 않도록)
- 두 예배를 모두 드린 사람도 한 번만 세요. 둘 중 하나만 골라 체크해 주세요.
- 이 기능이 생기기 전에 체크한 출석은 1부(노랑)로 보여요.

**Q. 2부로 눌렀는데 "저장하지 못했어요"가 뜨거나, 새로고침하면 노란색(1부)으로 바뀌어요.**
서버 설정이 예전 버전이에요. 회장이 새 `supabase/schema.sql` **전체**를 SQL Editor 에서 **Run** 해 주세요. (데이터는 그대로예요)
그다음 2부였던 사람을 2부로 한 번 더 눌러 주면 돼요.

**Q. 명단에서 빼는 것과 완전히 삭제하는 것은 뭐가 달라요?**
**명단에서 빼기**는 그 주일부터 출석부에 안 나오고 지난 기록은 남아요. 보통은 이것을 써요.
**완전히 삭제**는 그 사람의 출석 기록까지 모두 지워요. 이름을 잘못 넣었을 때만 써 주세요.

**Q. 출석부를 인쇄하고 싶어요.**
PC에서 **출석보고 → 출석부 표 → 인쇄 / PDF**. 전체(A4 가로), 목장별로 한 장씩(A4 세로), 한 목장만 중에 골라요.
결석 사유만 정리한 표는 **출석보고 → 결석 심방보고 → 인쇄 / PDF** 예요. 파일로 받으려면 **Word로 받기 / 엑셀로 받기**.

**Q. 임원 단톡방에 보고하고 싶어요.**
**출석보고 → 결석 심방보고** 에서 **전체** 또는 목장 하나를 고르고 **글 복사하기** → 단톡방에 붙여 넣어요.
휴대폰에서는 **공유** 로 카톡을 바로 고를 수도 있어요.

**Q. 목자와 총무가 동시에 눌러도 괜찮아요?**
네. 서로 화면에 바로 반영돼요. 인터넷 상태에 따라 늦어도 30초 안에 맞춰져요.
같은 사람을 둘이 동시에 다르게 누르면 마지막에 누른 것이 남아요. 두 사람이 동시에 **완료** 를 눌러도 알림은 한 번만 가요.

**Q. "저장하지 못했어요"가 떠요.**
인터넷이 잠깐 끊긴 경우가 많아요. 와이파이·데이터를 확인하고 다시 눌러 주세요.

**Q. "서버에 연결하지 못했어요"가 계속 떠요.**
Supabase 프로젝트가 일시 중지됐을 수 있어요(5번 비용 참고). 회장이 Supabase 대시보드에서
프로젝트를 열고 **Restore project** 를 눌러 주세요. 몇 분 뒤 다시 열면 돼요.

**Q. "서버 준비가 아직 안 됐어요"가 떠요.**
4-2의 스크립트를 아직 실행하지 않았거나 일부만 붙여 넣은 경우예요. `supabase/schema.sql` **전체**를 다시 붙여 넣고 Run 해 주세요.

**Q. 빌드가 "Supabase 설정이 없어요" 오류로 멈춰요.**
일부러 멈추게 해 둔 거예요. 서버 주소·열쇠 없이 만들면 **체험판**이 되어, 출석이 각자 휴대폰에만 저장되고 모이지 않아요.
게다가 체험판에는 실제 명단이 들어 있어서 인터넷에 올리면 안 돼요.
- **방법 A(내 컴퓨터)**: `app` 폴더의 `.env` 에 `VITE_SUPABASE_URL=`, `VITE_SUPABASE_ANON_KEY=` 뒤 값이 있는지 확인하고
  다시 `npm run build`. (파일 이름이 `.env.txt` 처럼 바뀌지 않았는지도 확인해요)
- **방법 B(Vercel)**: **Settings → Environment Variables** 에 값을 넣고 **Deployments → ⋯ → Redeploy**.

**Q. "잠시 잠겼어요"가 떠요 / 비밀번호를 잊어버렸어요.**
잠금은 **그 기기(그 와이파이)만** 해당돼요. 10분쯤 기다리거나, 휴대폰 데이터(LTE/5G)로 바꿔 보세요.
바로 풀거나 비밀번호를 `0000` 으로 되돌리려면, Supabase **SQL Editor** 에서 필요한 한 줄만 붙여 넣고 **Run** 하세요.

```sql
-- 잠금 바로 풀기 (모든 기기)
delete from public.login_attempts;

-- 비밀번호를 0000 으로 되돌리기 (그다음 앱에서 바로 6자리 이상으로 바꿔 주세요)
update public.app_settings set value = extensions.crypt('0000', extensions.gen_salt('bf')) where key = 'passcode_hash';
```

**Q. 다른 교회·다른 청년부도 쓸 수 있어요?**
네. 4번을 처음부터 따라 해서 Supabase 프로젝트를 하나 더 만들면, 완전히 따로 쓰는 출석부가 돼요.
(이때 `src/lib/seed.json` 의 체험용 명단은 빈 목록이나 지어낸 이름으로 바꿔 주세요)

## 개발자 메모

- Vite + React + TypeScript + Tailwind CSS + zustand. 명령: `npm run dev`, `npm run build`, `npm run typecheck`
- 탭 구조: `store.ts` 의 `Tab` = `'attend' | 'report' | 'stats' | 'calendar' | 'groupReport' | 'manage'`.
  아래 탭·PC 메뉴는 큰 탭 4개(출석부·캘린더·목장보고서·관리)이고, 출석부는 `tab` 이 attend·report·stats 중 하나일 때 켜져요.
  출석부 안쪽 탭은 `components/AttendSectionTabs.tsx` 가 `PageHeader` 의 `nav` 자리에 그려요. 마지막으로 본 안쪽 탭은 `attendTab` 에 남아요.
  탭 이동은 꼭 `goTab(t)` 로 해요 (목장 화면의 '뒤로 가기' 기록 정리 + 맨 위로). `setTab` 은 상태만 바꿔요.
- 캘린더·목장보고서 데이터는 main store 가 아니라 각자 저장소가 불러와요. main store 의 `refresh('calendar' | 'reports')` 는 아무것도 안 해요.
- `src/backend/local.ts`: 체험 모드 (localStorage, 같은 브라우저 탭끼리 BroadcastChannel). `src/backend/supabase.ts`: 실제 서버.
  `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 가 있으면 실제 서버를 써요.
- 빌드: `vite.config.ts` 가 `vite build` 때 두 값이 없으면 일부러 실패해요(체험판을 실수로 배포하지 않도록).
  체험판을 일부러 만들 때만 `VITE_DEMO=1 npm run build`. `npm run dev` 는 그대로 체험 모드로 떠요.
  `VITE_VAPID_PUBLIC_KEY` 는 없어도 빌드되고, 그때는 Web Push 만 꺼져요.
- 체험 명단: `src/lib/seed.json` = 2026.10.11 엑셀 출석부의 **실제** 명단(9개 목장 186명).
  `local.ts` 가 `VITE_SUPABASE_URL` 이 비었을 때만 `import('../lib/seed')` 해서, 서버용 빌드의 `dist` 에는 이름이 들어가지 않아요.
  (서버용 설정으로 `vite build` 한 결과에서 명단 이름이 검색되지 않는 것을 확인했어요) 저장소는 Private 이어야 해요.
- 서버(`supabase/schema.sql`): 모든 표에 RLS 를 켜고 정책은 두지 않아요. 앱은 `am_` 로 시작하는
  `SECURITY DEFINER` 함수만 부르고, 함수마다 공용 비밀번호(`p_code`)를 bcrypt 해시와 비교해요(`am__verify`).
  - `am__verify` 는 맨 먼저 읽기 전용 트랜잭션(`transaction_read_only = on`), `request.method` 가 POST 가 아닌 요청,
    `Prefer: tx=rollback` 을 맞든 틀리든 같은 오류(`AM_POST_ONLY`)로 거절해요. (PostgREST 는 GET/HEAD `/rpc` 를 읽기 전용으로 실행해서
    틀린 기록을 남길 수 없기 때문). 앱은 `sb.rpc()` 기본값인 POST 만 써요.
  - 한 트랜잭션에서 `am__verify` 는 한 번만 돼요(`am.verified`, 두 번째는 `AM_ONE_CALL`). GraphQL 등으로 여러 번 묶어 보내고
    통째로 되돌려 틀린 기록을 지우는 우회를 막아요. 그래도 `pg_graphql` 은 꺼 두기를 권장해요(4-3).
  - 기기 구분(`am__client_key`): `request.headers` 의 `cf-connecting-ip` → `x-forwarded-for` 첫 값 → `x-real-ip` → `'unknown'`.
    IPv6 는 /64 로 묶고, 표에는 `attempt_salt` 를 섞은 sha256 앞 32자(`h:…`)만 남겨요.
  - 틀린 값은 `login_attempts(client_key, code_hash)` 에 남기고(같은 기기·같은 값은 10분에 한 번),
    한 기기가 10분 안에 서로 다른 값 10개(`'unknown'` 묶음은 15개)가 되면 그 기기의 모든 요청을 막아요.
  - 비상 잠금: 전체에서 10분 안에 서로 다른 틀린 값이 100개 이상이면, `login_trusted`(최근 30일 안에 맞는 비밀번호를 보낸 기기)에 없는
    기기의 요청을 막아요. 같은 기기의 동시 요청은 `pg_advisory_xact_lock(hashtext('am_verify'), hashtext(client_key))` 로 하나씩 세요.
  - ⚠️ 실제 Supabase 에서 `request.headers` 에 어떤 IP 머리글이 오는지는 배포 뒤 한 번 확인해 주세요.
    (`login_attempts.client_key` 가 모두 `'unknown'` 이면 머리글이 안 오는 것이고, 그때는 전체 15개 잠금으로 동작해요)
- 명단 한 번에 넣기: `am_import_roster(p_code, p_groups, p_members)` — 목장이 하나라도 있으면 `{ error: 'exists' }`,
  아니면 한 트랜잭션으로 넣고 `{ ok: true }`. `pg_advisory_xact_lock(hashtext('am_import_roster'))` 로 한 번만 들어가요.
- 저장 순서: 같은 대상(출석 한 칸, 주일 메모, 명단, 목장 완료)의 저장은 `lane` 으로 하나씩 보내요. 인터넷이 잠깐 끊긴 저장은 한 번 다시 보내고,
  처리됐는지 모르는 실패(시간 초과, 502/504/520)는 다시 보내지 않고 다음 저장을 5초 늦춰요.
- 실시간: 저장 뒤 Realtime broadcast `am-attendance` / `change` / `{ scope }` 를 보내고, 다른 기기는 받아서 다시 불러와요.
  개인 정보는 보내지 않아요. 화면이 보이는 동안 30초마다 새로고침으로도 맞춰요.
  출석 기록은 처음에 한 번 다 받고, 그다음에는 `am_get_attendance_changes` 로 바뀐 것만 받아요.
- 예배 구분: `attendance.service` (`smallint`, 1 = 1부 / 2 = 2부, 출석이 아니면 `null`). 값이 없는 예전 출석 기록은 1부로 봐요.
  `am_save_attendance` 는 `{ ok, service }` 를 돌려주고, 앱은 `service` 가 없는 응답(= 예전 스크립트)에서 2부를 저장하면 "다시 Run" 안내를 내요.
- 목장 완료: `group_days(date, group_id, state 'done'|'editing', done_at, edit_count, pushed_at, push_token, push_token_at)`.
  `am_set_group_day(p_code, p_date, p_group_id, 'complete'|'edit')` 가 advisory lock 으로 하나씩 처리하고
  `{ ok, notify: 'done'|'edited'|null, pushToken, day }` 를 돌려줘요
  (완료 전 → 완료 = done, 수정 중 → 완료 = edited + `edit_count` +1). 앱은 `state = 'done'` 이면 그 목장의 체크·추가를 막아요.
  - 서버 잠금: `am_save_attendance` / `am_clear_attendance` 는 그 주일에 `state = 'done'` 인 목장이면 아무것도 바꾸지 않고
    `{ error: 'group_done' }` 을 돌려줘요. 보낸 기록의 `groupId` 와 이미 저장된 줄의 `group_id` 를 둘 다 봐요
    (완료된 목장으로 옮기기·거기서 빼기도 막아요). `editing` 이면 저장돼요. 주일 메모(`am_save_week_note`)는 목장별이 아니라서 막지 않아요.
    완료 처리와 겹치지 않도록 저장은 같은 advisory 열쇠에 shared 잠금(`am__group_done`)을 걸고, `am_set_group_day` 는 exclusive 로 잡아요.
  - 앱(`supabase.ts`)은 `group_done` 을 `BackendError('conflict', "완료된 목장이에요. 고치려면 ‘수정’을 눌러 주세요", 'group_done')` 로 바꿔요.
    로그아웃하지 않고(로그아웃은 `kind === 'auth'` 만), 다시 보내지도 않아요.
- 완료 알림 (`src/lib/push.ts`, `src/components/notify/*`, `public/sw.js`)
  - 실시간: `notify` broadcast `{ kind, group, groupId, date, n }`. 받는 쪽은 `am_get_group_days` 로 서버 기록(`edit_count`, 30분 안의 `done_at`)과
    맞는지 확인한 뒤에만 화면 알림(8초, 최대 3개)을 띄워요. 문구는 `noticeText()`.
  - Web Push: `VITE_VAPID_PUBLIC_KEY` 가 있을 때만. 알림을 켠 기기는 앱을 열 때마다 `am_save_push_sub` 로 구독을 올려요(최대 300개, 오래된 것부터 정리).
    Web Push 에는 공용 비밀번호를 싣지 않아요. `am_set_group_day` 가 notify 를 돌려줄 때 한 번 쓰는 열쇠(`pushToken`, 48자 hex)를 만들어
    `group_days.push_token(_at)` 에 두고 응답에 넣어요. 이미 완료된 목장에 다시 `complete` 가 오면(응답이 끊겨 다시 보낸 경우) 새로 만들지 않고
    아직 안 쓴 열쇠를 그대로 돌려주고, `edit` 는 열쇠를 지워요. `supabase.ts` 는 열쇠를 메모리에만 `날짜|목장id` 로 들고 있다가
    `sendNotice()` 에서 Edge Function `am-notify` 를 `{ date, groupId, token, endpoint }` 로 부르고 바로 버려요(열쇠가 없으면 Web Push 만 건너뛰어요).
    함수는 service_role 로 `am_push_targets(p_date, p_group_id, p_token, p_exclude_endpoint)` 를 불러요(anon 은 못 불러요, 비밀번호 확인 없음).
    열쇠가 정확히 맞고, 만든 지 10분 안이고, 그 완료를 아직 안 알렸을 때만(`pushed_at`) 대상을 돌려주고 열쇠를 지워요. 아니면 `{ error: 'denied' }` → 함수는 403.
    문구는 서버 기록으로 정하고, 누른 기기(`endpoint`)는 빼요. 404/410 구독은 `am_push_forget(p_endpoint)`(service_role 전용)로 지워요.
    같은 알림은 `tag`(`am-날짜-목장-n`)로 하나로 합쳐져요. 예전 `am_push_targets(text, text, date, uuid)` 는 schema.sql 이 지워요.
  - CLI 로 올릴 때: `supabase functions deploy am-notify --no-verify-jwt`. Secrets: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
  - 시험한 범위: 함수는 가짜 서버로, 화면 알림은 체험 모드의 두 탭으로. **실제 휴대폰·실제 Supabase 에서 Web Push 를 끝까지 시험하지는 않았어요.**
